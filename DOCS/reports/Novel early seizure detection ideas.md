# Measure the seconds that others ignore

**Main finding: 2023-2026 TUSZ research almost never reports how many seconds pass between the start of a seizure and the alarm.** Because of this, the best way for you to "detect earlier than prior work" is to create and win a new, well-defined measurement, not to add another accuracy score. The best offline TUSZ detector today, SeizureTransformer, reaches an event-level F1 of about 0.67 (sensitivity 0.72). It uses 60-second windows and non-causal post-processing, so it cannot tell you how early it fires. The standard scoring tool (SzCORE) also counts an alarm as correct if it fires up to 30 seconds before the seizure or anywhere during it, so it hides latency completely. The published onset latencies (about 2-5 s) come from CHB-MIT with patient-specific models. Cross-patient models on the same data take about 8-16 s. No paper we found reports latency for each seizure type on TUSZ. Focal seizures, which are much harder to detect than generalized ones, are probably where the delays are longest. EEG foundation models (large models pretrained on thousands of hours of EEG) are small enough (2-7 million parameters) to fine-tune on one consumer GPU. But independent benchmarks show that their gains over strong small models are modest and not consistent. Only two 2026 models are built for real-time streaming. Implants such as NeuroPace RNS already use very simple "relative change" detectors that fire seconds after onset. They run on microwatt power budgets, and every false detection costs battery. **Our recommendation:** build a causal, type-aware early-alarm system on TUSZ. It adds a sequential change-detection layer (CUSUM) and a conformal false-alarm guarantee on top of a small backbone. Report onset latency per seizure type at a fixed false-alarm budget. This project is novel, fits limited compute, and connects directly to implant constraints.

## Nobody reports seconds-to-alarm on TUSZ, so the metric is the opportunity

### Key terms used in this report

| Term | Simple meaning |
|---|---|
| **Onset latency (detection delay)** | Seconds from the expert-marked seizure start to your first alarm. This is different from *processing latency* (how long the computer takes to run the model). |
| **Causal model** | A model that uses only past and present EEG, never future samples. Only causal models can run live. |
| **Event-level scoring** | Each seizure counts as one "event", found or missed, instead of scoring every small window. |
| **FA/h, FP/24h** | False alarms per hour or per day: alarms when no seizure is happening. |
| **Cross-patient (patient-independent)** | Test patients are never seen during training. This is harder and more realistic than patient-specific training. |
| **SPH / SOP** | For *prediction*: seizure prediction horizon (gap before onset) and seizure occurrence period (the window where the seizure must happen). |

The strongest recent TUSZ detector is **SeizureTransformer**, which won the 2025 Seizure Detection Challenge. On the TUSZ v2.0.3 test set it scores **event F1 0.671, sensitivity 0.717, precision 0.631** ([arXiv 2504.00336](https://arxiv.org/html/2504.00336v3)). It uses 60 s windows, a 0.8 threshold, morphological opening/closing, and a 2 s minimum seizure length. This is an offline design, and the paper reports no onset latency ([arXiv 2504.00336](https://arxiv.org/html/2504.00336v3)). A 2026 Scientific Reports benchmark with CatBoost ensembles reaches **event sensitivity 0.75 at 0.68 false alarms per hour** (about 16 per day), with window AUROC 0.92 ([Sci Rep 2026](https://www.nature.com/articles/s41598-026-41358-w)). The same paper reports that seizures lasting 30-90 s were found only **4 of 12 times (0.33)**, compared with **0.77 for seizures longer than 90 s** ([Sci Rep 2026](https://www.nature.com/articles/s41598-026-41358-w)). One of our notes could not open the full text, so check these numbers before you quote them. The Temple group's real-time system shows how much a live system costs in accuracy. It reaches only **42% sensitivity at 5.78 FA/24h** on the TUSZ v1.5.2 dev set. Its "300 ms latency" is processing time, not seconds from onset ([arXiv 2202.07796](https://arxiv.org/abs/2202.07796)). Tiny models are also competitive: REST reaches clip AUROC 83.6 on TUSZ with only **about 9,000 parameters (37 KB)** and 1.29 ms inference ([arXiv 2406.16906](https://arxiv.org/html/2406.16906)).

Latency numbers exist only outside TUSZ, and they are mostly patient-specific. Xu et al. treat detection as probabilistic prediction with soft labels. They report **2.3 ± 0.7 s latency on CHB-MIT and 4.7 ± 2.0 s on SWEC-ETHZ (intracranial EEG)**, with about 0.08 false detections per hour. They trained one model per patient ([arXiv 2301.03465](https://arxiv.org/html/2301.03465)). Their comparison table shows that older **cross-patient** methods take much longer: a 1D-CNN needs 8.1 s on CHB-MIT and 13.2 s on SWEC-ETHZ, and another method needs 15.9 s ([arXiv 2301.03465](https://arxiv.org/html/2301.03465)). Other papers claim 1.2-2.0 s on CHB-MIT ([PMC10773586](https://pmc.ncbi.nlm.nih.gov/articles/PMC10773586/); [PMC13574979](https://pmc.ncbi.nlm.nih.gov/articles/PMC13574979/)), but we saw these only in search snippets. **So a cross-patient TUSZ system with median latency under about 10 s at a low false-alarm rate would already be a strong, new result.** Be careful with definitions. Some papers measure latency from the *end* of the analysis window and others from the *start*, and this can change the number by a whole window length ([arXiv 2301.03465](https://arxiv.org/html/2301.03465)).

The standard scoring hides earliness. The SzCORE/timescoring library allows **30 s before and 60 s after** each seizure. It merges events closer than 90 s, splits events longer than 5 min, and outputs only sensitivity, precision, F1 and FP/24h, with **no latency output** ([timescoring GitHub](https://github.com/esl-epfl/timescoring); [SzCORE, arXiv 2402.13005](https://arxiv.org/abs/2402.13005)). A model that fires 25 s late gets the same score as one that fires 1 s after onset. The 2025 challenge also did not score latency ([arXiv 2505.18191](https://arxiv.org/abs/2505.18191)).

Generalization to new hospitals is the second big problem. In the 2025 challenge, 28 algorithms trained on public data (mainly TUSZ) were tested on 4,360 hours of private EEG from 65 patients in Dianalund. The winner reached only **event F1 32%, sensitivity 37%, precision 29%, at 1.34 false positives per day** ([arXiv 2505.18191](https://arxiv.org/abs/2505.18191)). The SeizureTransformer paper reports a higher challenge F1 (0.43). This is probably due to a different way of averaging, so the organizers' number is the official one ([arXiv 2504.00336](https://arxiv.org/html/2504.00336v3)). **The top TUSZ model loses about half of its F1 on a new site.** Any "early detection" claim should therefore include at least one test on a different dataset.

True *prediction* (warning before onset) on TUSZ is still weak. MLSPred-Bench turns TUSZ into 12 patient-independent prediction tasks (SPH 2-30 min, SOP 1-5 min). Its best reported result, at SPH 30 / SOP 2, is **AUC 80.5%, sensitivity 70.3% but specificity only 59.6%**. Its metrics are per segment, not per alarm ([PMC12423417](https://pmc.ncbi.nlm.nih.gov/articles/PMC12423417/)). Very impressive CHB-MIT claims, such as predictions **76.8 minutes before onset**, come from patient-specific models with a segment-level false-positive rate of **33.6 per hour**, which is not usable in a clinic ([J Neural Eng 2024](https://iopscience.iop.org/article/10.1088/1741-2552/ad9ad0)). Random segment splits also leak data from the same patient into training and testing, which inflates results ([R Soc Open Sci 2024](https://royalsocietypublishing.org/doi/10.1098/rsos.230601)). **For a 4-6 month project, "detect within the first few seconds, reliably, per type" is a more defensible goal than "predict minutes ahead".**

## Foundation models help a little, and only two of them are built for streaming

Most useful EEG foundation models (FMs) are small. **CBraMod has 4.0M parameters, LaBraM-Base 5.8M, BIOT 3.2M, LUNA-Base 7M, and S-CEReBrO 2.4M.** Most are pretrained on the TUH EEG Corpus (TUEG) and use 1-second patches ([CBraMod](https://arxiv.org/html/2412.07236); [LaBraM](https://arxiv.org/html/2405.18765); [LUNA](https://arxiv.org/pdf/2510.22257); [S-CEReBrO](https://arxiv.org/abs/2607.27913)). Pretraining is expensive (for example, CBraMod needed about 5 days on 4 GPUs), but you only fine-tune, and models this small fit on one consumer GPU ([CBraMod](https://arxiv.org/html/2412.07236)). No paper measured the exact memory use on consumer GPUs, so this is an estimate from model size. Some models handle any electrode layout: CBraMod uses its ACPE positional encoding, LUNA compresses any channel set into fixed "latent queries", and REVE uses a 4D positional encoding ([CBraMod](https://arxiv.org/html/2412.07236); [LUNA](https://arxiv.org/abs/2510.22257); [REVE](https://arxiv.org/abs/2510.21585)). This is useful for reduced-channel or wearable montages. BIOT accepts at most 18 channels ([CBraMod](https://arxiv.org/pdf/2412.07236)).

The strongest seizure evidence for FMs is on CHB-MIT. There, CBraMod improves balanced accuracy from 0.57-0.64 (EEGNet, CNN-Transformer) to **0.74**, and AUPRC from about 0.19-0.25 to **0.37** ([CBraMod](https://arxiv.org/pdf/2412.07236)). However, that test set has only 2 patients. When the S-CEReBrO team re-ran the models under its own protocol, CBraMod (84.6 AUROC) and LaBraM (79.7) fell **below the best supervised baseline (86.6)**. S-CEReBrO itself reached 87.5 ([S-CEReBrO](https://arxiv.org/pdf/2607.27913)). Independent benchmarks point the same way. EEG-FM-Bench finds that frozen FMs generalize poorly and that pretraining mostly acts as a "time-series aware initialization" ([arXiv 2508.17742](https://arxiv.org/abs/2508.17742)). NeuroAtlas found that on TUSZ-style seizure tasks, only NeuroLM and REVE clearly beat a randomly initialized CBraMod (**about 0.55 vs 0.44**), and EEG FMs did not consistently beat general time-series FMs ([NeuroAtlas](https://arxiv.org/html/2605.14698v1)). A stress-test paper found that FM features identify *which dataset* a recording came from with AUROC 1.000. It also found that TUH makes up 44% of REVE's pretraining data, so TUH benchmarks are partly "in-domain" for REVE ([arXiv 2607.24519](https://arxiv.org/html/2607.24519v1)). One counterpoint: Brain4FMs reports that large-scale pretraining transfers better than task-specific training in most clinical settings ([arXiv 2602.11558](https://arxiv.org/html/2602.11558v1)). **In practice, an FM is a reasonable backbone to try, but you must compare it with a random-init copy of the same model and a strong small model, and you must check for overlap between the pretraining data and your test patients.**

How you fine-tune matters. Linear probing (training only a final linear layer) works badly for seizures. For example, BIOT on CHB-MIT gets AUPRC **1.5% with a linear probe but 31.5%** after adapting only its last encoder layer ([arXiv 2608.24727](https://arxiv.org/html/2608.24727)). LoRA (low-rank adapters, which train a few small extra matrices) cuts LaBraM's trainable parameters from 5.8M to about 68k without losing accuracy on BCI tasks ([arXiv 2507.01196](https://arxiv.org/html/2507.01196)). For 2-7M models, full fine-tuning is already cheap, so LoRA matters mainly for larger models or for per-patient adaptation.

For *early* detection, the model design matters more than the model size. Most FMs process fixed 5-30 s windows. Their latency is roughly window length plus stride, and they recompute overlapping context. **Only two 2026 models target streaming.** CaMBrain is a causal Mamba-3 state-space model (36.7M parameters). It updates every 62.5 ms and keeps a memory across the whole recording. Keeping this memory raises the average seizure probability at onset from 11.8 to 25.2 on CHB-MIT, and in one recording the probability starts rising **about 15 s before the annotated onset** ([CaMBrain](https://arxiv.org/abs/2605.28792)). That is a single example, and its code release is unconfirmed. S-CEReBrO (2.4M, code in pulp-bio/biofoundation) keeps memory constant however long the signal is, and can run on 14-hour recordings ([S-CEReBrO](https://arxiv.org/abs/2607.27913)). FEMBA has been quantized for microcontrollers, but it is bidirectional, so it is not causal as published ([arXiv 2603.26716](https://arxiv.org/abs/2603.26716)). **We found no FM paper that reports onset latency in seconds on TUSZ, or TUSZ seizure-type classification.** Both are open.

## Implants detect seizures seconds late, with microwatt budgets

NeuroPace RNS is the main clinical closed-loop seizure device (it detects a seizure and then stimulates). Its detectors are very simple. Each of its 4 intracranial channels compares one feature (line-length, area, or a bandpass "half-wave" count) with a threshold. A typical setting is a **66% change in line-length over 2 s compared with a 2-minute sliding baseline**. The device cannot see activity above 125 Hz ([RNS programming review, 2026](https://pmc.ncbi.nlm.nih.gov/articles/PMC13285825/)). This is a relative-change detector, which is a simple form of the sequential change detection proposed below. When it fires, RNS delivers short **100-200 ms, 200 Hz bursts**. The battery lasts more than 10 years, but **it is at risk when daily therapies exceed 6,000** ([RNS review](https://pmc.ncbi.nlm.nih.gov/articles/PMC13285825/)). So in an implant, every false detection costs battery life. Over 9 years, RNS gave a **75% median seizure reduction**, and about one-third of patients had at least a 90% reduction ([Neurology 2020](https://pubmed.ncbi.nlm.nih.gov/32690786/)). Detection usually comes several seconds after electrographic onset. One snippet reports that adaptive tuning cut median delay from 12.3 s to 4.8 s in the slowest patients ([Epilepsia 2023](https://onlinelibrary.wiley.com/doi/abs/10.1111/epi.17666)), but we could not confirm the primary paper.

There is an important caveat for your motivation. Recent evidence suggests that much of RNS's benefit comes from **chronic neuromodulation** (slow, long-term changes in the brain) rather than from stopping each seizure quickly. Closed-loop and open-loop outcomes look similar. Super-responders received stimulation mostly during the *rising phase of multiday seizure risk* ([Communications Medicine 2023](https://www.nature.com/articles/s43856-023-00401-x); [RNS review](https://pmc.ncbi.nlm.nih.gov/articles/PMC13285825/)). We found no human randomized trial showing that earlier detection gives better outcomes. **So "earlier is better" is a plausible engineering goal, not a proven clinical fact.** Your report should say this honestly. Chip papers aim for about 1 s: one closed-loop chipset reports **0.76 s latency with 97.8% sensitivity** (from a snippet) ([ResearchGate](https://www.researchgate.net/publication/261045332_A_Fully_Integrated_8-Channel_Closed-Loop_Neural-Prosthetic_CMOS_SoC_for_Real-Time_Epileptic_Seizure_Control)).

High-channel BCIs are not epilepsy products. No official Neuralink, Synchron or Precision epilepsy application was found. Neuralink's 2019 paper gives **5.2 µW per analog channel, about 6 mW per chip, and 550-750 mW per system** ([JMIR 2019](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC6914248/)). Paradromics' first human recording took place during an epilepsy surgery, but its goal is communication ([Michigan Medicine](https://www.michiganmedicine.org/news-release/university-michigan-implants-first-human-paradromics-wireless-brain-computer-interface-designed)). Seizure-detection hardware runs at tens to hundreds of microwatts. A spiking neural network (SNN) on the Xylo chip used **about 375 µW** for about 93% accuracy ([arXiv 2410.16613](https://arxiv.org/abs/2410.16613)), and the NeuralTree chip uses **0.227 µJ per classification** ([arXiv 2205.06090](https://arxiv.org/pdf/2205.06090)). **An implant-ready model therefore needs thousands to tens of thousands of parameters, not millions.** REST-sized models fit this budget, and CBraMod-sized models do not.

The devices closest to TUSZ-style scalp EEG are sub-scalp monitors: Epiminder Minder (FDA De Novo) and UNEEG EpiSight (FDA 510(k), June 2026). They record for months to years with very few channels ([Epiminder](https://epiminder.com/news/fda-authorisation); [GS MedTech](https://news.gsmedtech.com/uneeg-medical-fda-510k-clearance-for-uneeg-episight-system/)). The commercial accuracy bar is high. Ceribell Clarity reports 94% sensitivity and 95% specificity for high seizure burden ([Ceribell](https://ceribell.com/product/clarity/)). Empatica's EpiMonitor reports **0.02-0.05 false alarms per day**, but only for tonic-clonic seizures ([Empatica](https://www.empatica.com/epimonitor/how-it-works/)). The wearable SeizeIT2 study shows the problem clearly. Behind-the-ear EEG plus ECG reached 0.73 sensitivity but **6.22 false positives per hour** (precision 0.004) ([Epilepsia Open 2026](https://pmc.ncbi.nlm.nih.gov/articles/PMC13238671/)). Scalp EEG also shows seizures later than intracranial EEG, so TUSZ latency is a *pessimistic proxy* for implant latency. TUSZ is best used to develop methods and to pretrain, not to stand in for ECoG ([PMC8632629](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC8632629/)).

## Five gaps are open; three popular directions are crowded

We sorted the literature by how crowded each direction is. Seizure-type *classification* on clips is crowded, and results drop sharply when evaluation is honest. IBM's benchmark falls from weighted F1 0.90 with seizure-wise splits to **0.56 with patient-wise splits** ([Expert Syst Appl 2023](https://www.sciencedirect.com/science/article/pii/S0957417423015427); [IBM repo](https://github.com/IBM/seizure-type-classification-tuh)). The best graph model (Tang et al.) reaches 0.749 weighted F1 ([arXiv 2104.08336](https://arxiv.org/abs/2104.08336)). Reported TUSZ detection sensitivity is only **23-38% for focal seizures vs 60-81% for generalized seizures** across studies ([review](https://www.sciencedirect.com/science/article/pii/S0957417423015427), snippet). Yet no one reports latency *per type*. "Mamba beats CNN on CHB-MIT" papers are also crowded, with claims such as 99% accuracy ([arXiv 2601.13234](https://arxiv.org/abs/2601.13234)), and so are generic saliency-map add-ons.

Two more ideas are interesting but harder for you. EEG+ECG fusion (for example, whether a fast heart rate gives earlier warning for temporal seizures) needs you to first check how many TUSZ files have a usable EKG channel. ## Five project ideas, ranked for a student with one GPU

Scores are our judgement (1 = low, 5 = high). Feasibility assumes one consumer GPU or Colab and 4-6 months. Every idea uses the official TUSZ v2.0.x train/dev/eval split (patient-independent) and SzCORE event scoring via `timescoring`. Every idea also adds a **latency protocol**: median and interquartile range (IQR) of onset latency per detected seizure, sensitivity within ≤5/10/20 s of onset, and FP/24h at matched operating points. The protocol states whether latency is measured from the window end, and it counts alarms inside the 30 s pre-ictal tolerance as negative latency. These additions follow the gaps identified in [timescoring](https://github.com/esl-epfl/timescoring) and [Xu et al.](https://arxiv.org/html/2301.03465).

### Idea 1: a type-aware early alarm with a statistical false-alarm guarantee

**Hypothesis.** A causal detector with a short stride, combined with a CUSUM alarm, gives a lower median onset latency than fixed-threshold post-processing at the same FP/24h. (CUSUM, the cumulative sum test, adds up small pieces of evidence over time and fires when the total crosses a limit. In theory it is the fastest detector of a change for a given false-alarm rate.) The latency gap is largest for focal seizures (FNSZ, CPSZ). A conformal calibration step (it chooses the threshold from held-out data so that the false-alarm rate is statistically bounded) can hold FP/24h below a target, for example ≤ 2/day, on unseen patients.

**Method.** First, train a small causal backbone that outputs a seizure probability every 0.5-1 s from the past 2-4 s of EEG. Candidates are a CNN-GRU, or a REST-sized model for the "implant-ready" variant. Add an auxiliary head that predicts focal vs generalized. Second, turn outputs into log-likelihood ratios and run CUSUM. You can also run a Shiryaev-Roberts statistic, a close relative. Explain that the RNS line-length rule (change over 2 s vs a 2-min baseline) is a hand-made version of the same idea ([RNS review](https://pmc.ncbi.nlm.nih.gov/articles/PMC13285825/)). Third, calibrate the CUSUM threshold on the dev set with conformal or Learn-then-Test risk control, so FP/24h ≤ k with a stated confidence. This follows the Learn-then-Test prediction work ([PMC10543660](https://pmc.ncbi.nlm.nih.gov/articles/PMC10543660/)). Fourth, report everything per seizure type and per seizure duration, with patient-level bootstrap confidence intervals, because ABSZ/TNSZ/TCSZ have few patients.

**Datasets.** TUSZ v2.0.x as the main dataset. Siena or CHB-MIT for a cross-dataset check, which is needed because of the challenge's generalization gap ([arXiv 2505.18191](https://arxiv.org/abs/2505.18191)).

**Metrics.** SzCORE event sensitivity, precision, F1 and FP/24h. Median/IQR latency. A **delay-vs-FP/24h curve**, which is the standard way to compare quickest-change detectors. Per-type sensitivity and latency. Parameter count and MACs per second, to connect to the implant budget.

**Baselines to beat.** Latency has no published TUSZ baseline, so *you create the baseline*. Measure the latency of (a) your backbone with the standard threshold + 2 s minimum-duration post-processing, (b) a line-length/RNS-style relative-change detector, and (c) SeizureTransformer, if its released model can be run causally or with its standard pipeline (check its code). For accuracy, stay close to event F1 0.67 / sensitivity 0.72 ([arXiv 2504.00336](https://arxiv.org/html/2504.00336v3)), or to sensitivity 0.75 at 0.68 FA/h ([Sci Rep](https://www.nature.com/articles/s41598-026-41358-w)). Clearly beat the causal 42% at 5.78 FA/24h ([arXiv 2202.07796](https://arxiv.org/abs/2202.07796)). Target a cross-patient median latency below the 8.1 s cross-patient CHB-MIT reference ([arXiv 2301.03465](https://arxiv.org/html/2301.03465)).

**Why it is novel.** Each part (per-type latency, CUSUM on deep outputs, conformal alarm control) is open on TUSZ, and no one has combined them. It is cheap because steps 2-4 are post-processing that runs on a CPU.

### Idea 2: few-channel behind-the-ear early detection with sim-to-real transfer

**Hypothesis.** When you reduce TUSZ to behind-the-ear channels (T7/P7/T8/P8), generalized seizures keep short latency, but focal and frontal seizures lose both sensitivity and speed. A model trained on simulated TUSZ montages transfers to real SeizeIT2 behind-the-ear recordings better than a model trained from scratch.

**Method.** Train the same causal detector on 22 → 8 → 4 → 2 channel subsets. Measure per-type latency and FP/24h at each level. Then test zero-shot and after light fine-tuning on SeizeIT2. The 4-channel TUSZ study reached AUC 85.9% and sensitivity 81% but used only segment metrics ([arXiv 2606.11970](https://arxiv.org/html/2606.11970)). SeizeIT2 has more than 11,000 hours and 883 focal seizures ([Sci Data 2025](https://www.nature.com/articles/s41597-025-05580-x)). **Baselines:** the 4-channel CNN-Merged result, and SeizeIT2's clinical algorithm (sensitivity 0.73 at 6.22 FP/h) ([PMC13238671](https://pmc.ncbi.nlm.nih.gov/articles/PMC13238671/)). **Impact:** this connects directly to sub-scalp devices like UNEEG EpiSight. **Risk:** SeizeIT2 is large, so data handling takes time. It works well as a chapter of Idea 1.

### Idea 3: causal streaming fine-tuning of a foundation model

**Hypothesis.** A pretrained causal or streaming FM (S-CEReBrO, or CaMBrain if its weights are released) reaches lower onset latency than CBraMod with sliding windows and than a random-init copy, at equal FP/24h. The biggest gain should come in the first seconds of focal seizures.

**Method.** Fine-tune S-CEReBrO (2.4M) and CBraMod (4M) on TUSZ with short strides. Compare them with EEGNet or a CNN-Transformer and with random-init versions. Document any overlap between the pretraining corpus and TUSZ eval patients. **Baselines:** CBraMod's CHB-MIT numbers ([CBraMod](https://arxiv.org/pdf/2412.07236)) and the re-run results showing FMs near supervised models ([S-CEReBrO](https://arxiv.org/pdf/2607.27913)). **Risk:** S-CEReBrO is from September 2026 and has little outside replication, and CaMBrain's code is unconfirmed. The benchmarks suggest the FM gain may be small ([NeuroAtlas](https://arxiv.org/html/2605.14698v1)). This is still a valid result, but it gives a weaker headline.

### Idea 4: streaming test-time adaptation when seizures are rare

**Hypothesis.** Standard entropy-minimizing test-time adaptation (for example Tent, which updates batch-norm layers on unlabeled test data) collapses toward "no seizure" in long streams where seizures are rare. A seizure-safe variant, for example one that updates only on confident background data, reduces FP/24h on a new site without increasing latency.

**Method.** Train on TUSZ, then adapt online on Siena/CHB-MIT or on held-out TUSZ patients. **Baseline:** the snippet-reported TTA result on CHB-MIT/Siena ([IJNS 2026](https://www.worldscientific.com/doi/10.1142/S0129065726500425)). **Risk:** the failure mode may be hard to fix within the time limit.

### Idea 5: short-horizon prediction with honest alarm metrics

**Hypothesis.** On MLSPred-Bench at SPH 2-5 min, alarm-level evaluation (sensitivity, false predictions per hour, time-in-warning) shows that current segment-level results overstate usefulness. A calibrated alarm layer (as in Idea 1) improves the trade-off. **Datasets:** MLSPred-Bench, which is more than 150 GB ([GitHub](https://github.com/pcdslab/MLSPred-Bench)). **Baseline:** ResNet at AUC 80.5% ([PMC12423417](https://pmc.ncbi.nlm.nih.gov/articles/PMC12423417/)). **Risk:** high. Cross-patient pre-ictal signal is weak, and storage may be a problem.

## Pick Idea 1, and add a few-channel chapter if time allows

**Idea 1 is our recommendation.** It is the only one that directly answers "earlier than prior work" with a number no one has published. It is aware of seizure type by design, and most of its new parts run on a CPU. Its alarm-budget framing matches the RNS battery limits ([RNS review](https://pmc.ncbi.nlm.nih.gov/articles/PMC13285825/)) and the false-alarm tolerance that regulators accept ([Empatica](https://www.empatica.com/epimonitor/how-it-works/)). Keep an "implant-ready" tiny variant (under about 50k parameters, REST-scale ([arXiv 2406.16906](https://arxiv.org/html/2406.16906))) next to your main model. Then you can say how much latency you lose when the model fits a microwatt budget. If you finish early, add Idea 2's channel-reduction analysis as a final chapter.

## Conclusion

The field has moved from "can we detect seizures?" to "can we detect them reliably on a new hospital's data?". The 2025 challenge shows that the answer is still only partly yes. Speed has not been measured on TUSZ at all. This changes what "novel" means for you. Your contribution is less about a new architecture and more about a new *measurement plus a guaranteed operating point*: how many seconds, for which seizure type, at how many false alarms per day. Foundation models and Mamba-style networks are tools you can plug in, not the contribution itself. The benchmarks suggest their gains will be small unless they are causal.

The implant view adds one more lesson. The clinical device that works today (RNS) uses simple relative-change rules, has a hard daily budget for detections, and may help patients mostly through slow neuromodulation rather than fast seizure abortion. So an honest early-detection project should report latency *and* its false-alarm and compute cost together. It should also say plainly that the clinical value of saving a few seconds is still unproven. A project that measures these trade-offs clearly, per seizure type, will be useful to the next person designing an implant or a sub-scalp monitor, whichever detector wins.
